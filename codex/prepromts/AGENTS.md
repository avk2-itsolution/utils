## Общий стиль

Пиши современный, читаемый код с понятными именами и типизацией.

Комментарии делай короткими и только по причине решения. Не дублируй код и docstrings.

Докстринги — на русском, коротко, желательно в одну строку.

Делай минимальные изменения. Не переписывай всё без явного запроса.

Не используй `+` в начале строк кода, чтобы код можно было сразу копировать в IDE.

Мало кода лучше, чем много кода, если решение остаётся корректным, читаемым и поддерживаемым.

Не плоди лишние переносы строк.

Используй типизацию там, где она улучшает читаемость:

```python
building: Building = token.get_building()
```

Для классов с данными, DTO и value objects почти всегда используй:

```python
@dataclass(slots=True)
```

Задавай уточняющие вопросы, если это реально влияет на решение. Но сначала старайся дать разумный рабочий вариант.

Предлагай более оптимальные подходы, альтернативы и риски, если видишь проблему в исходном решении.

## Backend / Bitrix24

Для времени в Django используй:

```python
from django.utils import timezone
```

Для Bitrix24 REST используй объект `but` — это `BaseBitrixToken`.

```python
but.call_api_method("crm.activity.add", task_data)
```

По задачам Bitrix24 REST не придумывай методы, поля, payload, response shape и события из памяти.

Сначала проверяй документацию через `bitrix-mcp-rest`.

## Ошибки и данные

Не скрывай ошибки через `pass`, молчаливый fallback или необоснованный `return None`.

Лучше упасть с понятной ошибкой, чем молча продолжить с некорректными данными.

Не злоупотребляй fallback-логикой:

```text
лишние or
дефолты "на всякий случай"
чтение значения из нескольких возможных ключей
проверки невозможных состояний
```

Если структура данных реально неясна — сначала уточни формат или проверь источник.

## UTF-8

Все файлы читать и записывать строго в UTF-8 без BOM.

Не перекодируй существующий русский текст.

Если в файле есть кириллица, не переписывай весь файл целиком без необходимости.

Перед записью проверь, что кириллица в diff отображается нормально, без mojibake.

Если есть риск поломать кодировку, не редактируй файл через shell here-string; используй точечный patch.

После изменений отдельно проверь изменённые файлы на mojibake.

## Production Read-Only Access

Для чтения данных портала и production database используй только read-only MCP tools.

Запрещено:

- использовать production credentials приложения;
- использовать admin webhook/token;
- использовать write-capable Bitrix24 token;
- запускать Django management commands против prod DB;
- выполнять SQL вне read-only MCP или read-only DB user;
- вызывать методы портала с записью: add, update, delete, set, bind, unbind, upload, import.

Разрешено:

- читать структуру данных;
- выполнять ограниченные SELECT-запросы;
- читать portal entities через allowlisted read methods;
- использовать данные только для диагностики, анализа и разработки.

Если read-only tool не даёт нужные данные — остановись и опиши, какого доступа не хватает.
